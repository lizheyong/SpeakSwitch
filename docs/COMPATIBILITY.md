# 兼容性记录

核查日期：2026-10-16。

声选把 Fn 的一次按下与松开，转发为当前应用的语音输入快捷键；Fn + Shift 调用单独配置的翻译快捷键。语音应用保持运行，切换时改变路由目标。

## 快捷键测试诊断

接入设置中的「3 秒后发送语音快捷键」会先准备目标应用，微信会同时选择其系统输入源。发送测试按键时启动最多一秒的观察，记录权限状态、所用投递路径及 HID / Session 观测点，并在发送前后各读取一次左右修饰键的按下状态。事件记录先按声选自有标记筛选，仅保存其合成事件的时间、类型、键码、修饰键和来源元数据，不记录其他应用中的键入内容。

日志保存在 `~/Library/Caches/Voice Switch/shortcut-test.log`，每次测试覆盖上一份。是否成功触发录音仍以原应用响应为准；权限或观测点日志只用于定位事件传递阶段。更多数据说明见 [数据与权限](../README.md#数据与权限)。

## 翻译的含义

翻译是可选的独立映射。填写翻译快捷键之前，应先在原应用确认该快捷键确实会进入所需的翻译功能。

- Typeless 官方文档说明：按翻译快捷键开始，按主语音快捷键结束；声选的 Fn + Shift 与 Fn 可分别映射这两个动作。
- Spokenly 使用 mode 和 AI Instructions 组织翻译行为，可给该 mode 单独配置快捷键。
- Chatterfly 的 AI 指令入口本身不能证明它等于独立翻译模式，需要在当前版本中验证具体动作。
- 其他模板的翻译能力保留为待确认状态，按当前版本的设置和实际结果记录。

声选转发快捷键，翻译目标语言、模式和结果由原应用管理。

## 共享词库兼容性

共享词库保存标准写法和备注。TXT 与 CSV 只导出标准写法；JSON 备份保留备注。提供给输入法的 CSV 使用 UTF-8、单列、无表头，每行一个词。含逗号或引号的词按 CSV 规则引用。

| 应用 | 已确认的词库入口或格式 |声选当前对接 |
| --- | --- | --- |
| Typeless | [官方说明](https://www.typeless.com/help/quickstart/history-and-dictionary)提供 Dictionary → New word → Import CSV；本机 2.8.1 界面文案要求单列、每行一个词，文件最大 5 MB | 生成单列 CSV、在 Finder 定位文件并打开应用，由用户在词库中完成导入 |
| Chatterfly | 本机 1.0.7.13415 的个人词库 → 添加新词包含「导入 CSV」；应用文案要求单列、每行一个词，包含导入预览 | 生成单列 CSV、定位文件并打开设置，由用户在词库中完成导入；不支持直接读取其本机数据库词条 |
| Spokenly | [Dictionary](https://spokenly.app/docs/custom-dictionary)按识别模型设置；ElevenLabs Scribe 的 Keyterms 使用逗号分隔，实时识别应用前 50 个词 | 导出词表供用户按模型要求填写；当前没有自动写入模型设置 |
| 闪电说 | [官方指南](https://shandianshuo.cn/docs)支持将人名、产品名和术语的标准写法加入词典；尚未核实批量导入格式 | 可导出通用词表，按当前版本词典界面添加 |
| 豆包输入法、微信输入法、自定义应用 | 尚未核实当前版本的词库导入格式 | 可导出通用词表，先确认原应用接受的格式 |

「准备导入」表示文件已生成。词库是否被接受、是否超出容量，以及最终导入数量，以原应用的预览和结果为准。当前没有后台双向同步；主词库的编辑、删除不会自动改变原应用已有词条。声选不写入第三方应用的私有词库数据库。

2026-10-15 本机验收：将声选生成的 CSV 交给 Chatterfly 1.0.7.13415，原生预览显示「共扫描到 6 条词汇，其中有效词汇 1 条」，并正确显示新增词语 `Voice Switch`。其他 5 条已存在于原词库。测试在预览阶段取消，未重复写入已有词条。

本机 Chatterfly 1.0.7.13415 的 `ybdict.sqlite` 中，`ybdict_terms.text` 保存的是编码或加密后的表示，与词库界面显示的明文不一致。行数一致只能证明存在记录，不能证明词条内容可用。当前没有可用的明文读取适配，声选不直接导入该数据库。已有词条需要通过兼容的词表文件导入，或在共享词库中手动维护；CSV 导入 Chatterfly 的入口与格式已单独确认。

标准词汇与纠错替换是两类设置。Spokenly 的 [Word Replacements](https://spokenly.app/docs/word-replacements)需要「原文本 → 替换文本」，并提供 [官方 CLI](https://spokenly.app/docs/macos/cli)和 JSON 备份；单独一个标准词不能自动推导出正确的替换规则。声选当前仅管理标准词汇，备注不会作为替换规则发送。

## Chatterfly 的特殊点

本机版本的快捷键设置包含以下提示：

- 「快捷键需要小于等于3个」
- 「暂不支持，推荐使用Fn/⌘/⌥/⌃/⇧的组合键」
- 「该按键不支持双击」

因此语音模板采用三个纯修饰键 `⌃⌥⇧`。是否接受该组合、是否响应合成事件，以原应用中的实际设置和触发结果为准。

纯修饰键快捷键需要避开其他快捷键的前缀。默认使用 `⌃⌥⇧`，让其他应用的 `⌃⌥⌘` 加数字，以及切换应用的 `⌃⌥⌘Space` 保持独立。翻译映射同样需要避免前缀冲突。

本机 Chatterfly 在没有列入当前启用的系统输入源时，仍运行全局语音功能。切换键盘输入源不能据此保证释放 Fn，接入步骤需要清理语音输入和 AI 指令等全部原生 Fn 绑定。

## 微信输入法的左右键标记

**2026-10-16，WeType 2.2.3（657）在此前原生界面构建通过真人验收：首次 Fn 开始并持续录音，第二次 Fn 正常结束，文字成功上屏。** 原应用的「启动语音输入」设置为左 Control + 左 Option + 2（`⌃⌥2`），原 `Fn + Space` 已释放。翻译未接入。

WeType 按左右修饰键标记识别快捷键，并要求系统当前选中微信输入模式。声选的事件携带通用标记及实际键码对应的左右标记；从 ABC 经声选选用微信输入法后，系统输入源已确认切换为 `com.tencent.inputmethod.wetype.pinyin`。

恢复修饰键使用独立的 `PhysicalModifierState`，跟踪 8 个左右修饰键的按下 / 松开边沿，忽略本应用标记的合成事件，避免将合成快捷键误当成仍按住的物理键。Fn 使用 Session 捕获，WeType 快捷键通过 HID 投递；首次发键在 Fn 回调返回后调度，组合保持 50 ms，连续触发释放间隔 25 ms。

本次验收的独立证据如下：

| 检查 | 结果 |
| --- | --- |
| 权限 | 辅助功能、输入监控与事件投递均为 `true` |
| 真实 Fn trace | 左 Control、左 Option、数字 2 各一次按下与松开，共 3 个按下、3 个松开事件 |
| 修饰键恢复 | 释放阶段跟踪到的物理修饰键为空，没有额外 Control / Option 按下事件 |
| CoreAudio 只读状态 | 记录到 12.720 秒的连续输入活动区间 |
| 用户实际操作 | Fn 开始、持续录音、再次 Fn 结束及文字上屏均正常 |

验收记录不包含音频或转写正文。声选在选用微信输入法或为它开启 One Fn 时选择系统输入源，不会持续锁定输入模式；手动切到 ABC 等其他输入源后，需要重新选用微信输入法。接入助手提供「重新准备试用」；接入设置中的延迟快捷键测试也会先为微信选择系统输入源。

## 自定义应用

通过「添加应用」选择 `.app`，设置名称、内部快捷键和备注。新工具、开源语音应用也使用相同流程。应用需要完成自身账号、模型、麦克风权限和上屏权限设置。

建议按以下顺序验收：

1. 直接按原应用的内部语音快捷键，确认按一下开始、再按一下结束，并且文字进入目标输入框。
2. 需要翻译时，直接测试原应用的翻译快捷键和结束方式。
3. 使用声选的快捷键测试，确认合成事件能触发原应用。测试会延迟发送快捷键，便于切换到空白文字输入框；如开始录音，在原应用中结束。
4. 开启 One Fn，测试 Fn 开始和结束、Fn + Shift 翻译，以及文字上屏的位置。
5. 切换到另一已接入应用，确认只有当前路由目标响应。
6. 测试平时使用的 Fn + Delete 等组合键。

## 运行边界

- 所有正在运行的语音应用都需要移除原生 Fn 绑定，包含 Fn + Shift、翻译、语音指令等附加功能。
- macOS 自身的 Fn 动作与听写快捷键也需要避开 Fn。
- 当前路由目标由声选管理；原应用实际是否开始录音，需要看原应用的状态。
- 切换前先结束当前录音。声选的按键指示仅表示 Fn 按下，当前没有跨应用的统一录音状态控制。
- 外接键盘的 Fn 若只在键盘固件内部工作，macOS 无法将它提供给声选。
- 安全输入、权限变更以及第三方应用升级可能影响快捷键事件。以当前输入框里的实际结果为准。
- Fn 松开时发送一次完整快捷键；原应用的单击模式决定录音如何切换。
- WeType 2.2.3（657）已在此前原生界面构建通过 Fn 开始、持续录音、结束和上屏的用户实测，翻译未接入。Typeless 与 Chatterfly 的真人验收对应功能构建 `9da51c9`，本轮整合构建仍待这两款应用回归；Chatterfly 翻译未接入。豆包输入法、Spokenly、闪电说尚未实测。

## Fn 占用预检（2026-10-19）

接入助手在专属快捷键设置前展示 Fn 检查清单，主界面和菜单栏提供入口。扫描包含已安装的目录内输入法、自定义应用、飞书 / Lark，以及 macOS 键盘与听写检查项。

- Typeless：读取 `app-settings.json` 中的 `featureShortcutBindings`，检查所有动作和附加绑定，可导入已识别的听写、翻译快捷键。
- 网易叭哥说：仅读取设置中的语音润色、翻译、随便问快捷键字段；数组形式优先于旧版单值。当前本机配置中，听写和翻译已经释放 Fn，随便问仍为 `Fn+Space`，预检能识别这一遗漏。
- 飞书 / Lark：检测安装后显示待检查；引导到「设置 → 效率 → 语音输入 → 立即设置」，把长按 Fn 改为例如 `⌃⌥9`。本机飞书 8.2.14 改键后，用户已确认 Typeless 在飞书中开始、结束、文字上屏正常，此验收对应此前安装构建。
